# Протокол·001 — ИИ-секретарь совещаний

Записывает совещание → расшифровывает речь → ИИ собирает структурированное
саммари (о чём встреча, цели, решения, задачи с ответственными и сроками,
важные детали, открытые вопросы) → красивая страница протокола, которую можно
скачать в Word.

**Стек:** Vite + React (SPA), serverless-функция Vercel `/api/extract`,
Anthropic Messages API (модель `claude-sonnet-4-6`). Расшифровка — в браузере
(Web Speech API), бесплатно.

```
Запись / вставка → расшифровка → ИИ-саммари (JSON) → страница протокола
                                                       ├─ скачать Word / копировать
                                                       └─ (Фаза 2) задачи → Notion
```

## Что под капотом

- **Лендинг** — описание потока и схемы саммари, кнопка «Начать запись».
- **Захват** — запись с микрофона (Web Speech API, `ru-RU` / `en-US`) или
  вставка текста, есть кнопка «Вставить демо».
- **`/api/extract`** — serverless-функция Vercel: хранит ключ в переменной
  окружения `ANTHROPIC_API_KEY`, зовёт Anthropic Messages API, возвращает строгий
  JSON по схеме из брифа. **Ключ никогда не попадает в браузер.**
- **Протокол** — страница по схеме саммари + «Скачать Word» (`.doc` через Blob)
  и «Копировать саммари». Тёмная тема, адаптив под телефон.

### Схема саммари (строгий JSON)

`тема`, `дата` (или `null`), `участники[]`, `краткое_резюме`, `цели_встречи[]`,
`ключевые_решения[]`, `задачи[{задача, ответственный, срок, приоритет:
высокий|средний|низкий, статус: "новая"}]`, `важные_детали[]`,
`открытые_вопросы[]`, `следующая_встреча` (или `null`).

## Локальный запуск

```bash
npm install

# 1) только фронт (без ИИ — кнопка «Собрать протокол» вернёт ошибку связи):
npm run dev

# 2) фронт + serverless-функция /api/extract (нужен Vercel CLI):
cp .env.example .env          # впишите ANTHROPIC_API_KEY
npm i -g vercel               # один раз
vercel dev                    # поднимет и фронт, и /api на одном порту
```

> При `npm run dev` Vite проксирует `/api` на `http://localhost:3000`
> (там работает `vercel dev`). Самый простой путь — запустить `vercel dev`.

## Деплой на Vercel

1. Импортируйте репозиторий в Vercel (фреймворк определится как **Vite**).
2. В **Project Settings → Environment Variables** добавьте
   `ANTHROPIC_API_KEY` (значение — ваш ключ Anthropic).
3. Deploy. Папка `/api` развернётся как serverless-функция автоматически.

Секреты — только в переменных окружения Vercel, не в коде.

## Переменные окружения

| Переменная          | Обяз. | Назначение                                            |
| ------------------- | ----- | ----------------------------------------------------- |
| `ANTHROPIC_API_KEY` | да    | Ключ Anthropic. Используется только `/api/extract`.   |
| `ANTHROPIC_MODEL`   | нет   | Переопределить модель (по умолчанию `claude-sonnet-4-6`). |
| `NOTION_TOKEN`      | нет\* | Токен интеграции Notion. Используется Notion-функциями. |
| `NOTION_DATABASE_ID`| нет\* | ID базы Notion «Совещания».                          |
| `NOTION_TASKS_DB_ID`| нет   | ID базы «Задачи». Если задан — задачи протокола уходят строками. |
| `TELEGRAM_BOT_TOKEN`| нет\*\* | Токен Telegram-бота (@BotFather) для рассылки задач.  |
| `NOTION_CONTACTS_DB_ID`| нет\*\* | ID базы «Контакты» (Имя → Telegram chat_id).      |

\* Нужны для «Завершить совещание» (шаги Notion) и «Истории встреч».<br>
\*\* Нужны для шага рассылки в Telegram (плюс `NOTION_TOKEN` для чтения базы
«Контакты»). Любого набора может не быть — соответствующий шаг просто
пропускается с пояснением, остальные выполняются.

## Завершить совещание

Одна кнопка **«Завершить совещание»** на странице протокола вызывает
`/api/finish-meeting`, которая делает всё одним запросом — **три независимых шага,
каждый в своём try/catch** (ошибка одного не роняет остальные). На сайте
показываются три строки результата.

**Шаг 1 — Совещание.** Создаёт страницу в базе `NOTION_DATABASE_ID`: title-свойство
«Тема» = тема; «Дата» (date) — если формат `YYYY-MM-DD` (иначе дата текстом в
тело); в тело — все разделы протокола. → ссылка на страницу.

**Шаг 2 — Трекер задач.** Читает схему базы `NOTION_TASKS_DB_ID`
(`GET /v1/databases/<id>`) и на каждую задачу создаёт строку, заполняя свойства
по их **реальному типу**: `title` → «Задача»; `rich_text` → «Ответственный» /
«Срок» / «Совещание»; «Приоритет» и «Статус» — `select` → `{select}`, `status` →
`{status}` (опция подбирается по базе без учёта регистра), иначе текстом. Если
конкретное свойство заполнить нельзя (например `status` без нужной опции) — оно
пропускается, **но строка всё равно создаётся**. → число созданных задач (или
текст ошибки Notion).

**Шаг 3 — Telegram.** Читает базу «Контакты» (`NOTION_CONTACTS_DB_ID`): title
«Имя» → колонка «Telegram». Группирует задачи по ответственному и тем, у кого
значение «Telegram» — **числовой `chat_id`**, шлёт личное сообщение с их задачами
через Bot API. → число отправленных и имена.

Все запросы к Notion — с `Authorization: Bearer <NOTION_TOKEN>` и
`Notion-Version: 2022-06-28`. Ответ: `{ meetingSaved, meetingUrl, tasksCreated,
tasksError, telegramSent, telegramRecipients }`.

**Настройка:** внутренняя интеграция Notion → `NOTION_TOKEN`; базы «Совещания»
(title «Тема», опц. «Дата» date), «Задачи» (title «Задача»), «Контакты» (title
«Имя», колонка «Telegram» с числовым chat_id) — каждой дать доступ интеграции;
бот @BotFather → `TELEGRAM_BOT_TOKEN` (получатель должен один раз написать боту
`/start`). Кнопки «Скачать Word» и «Копировать саммари» работают без всякой
настройки.

## История встреч

На лендинге блок «История встреч» при загрузке тянет `/api/list-meetings`,
которая запрашивает базу Notion (`POST /v1/databases/<id>/query`, сортировка по
дате создания по убыванию, лимит ~50) и возвращает `{ тема, дата, url }` для
каждой страницы. Новые — сверху, каждая строка — ссылка «Открыть в Notion →».
Состояния: загрузка, пусто, ошибка. Использует те же `NOTION_TOKEN` и
`NOTION_DATABASE_ID`.
